# 번역 스타일 가이드 (Brand Tone & Manner)

엔터프라이즈 B2B 기술 브랜드 콘텐츠를 다른 언어로 번역·현지화할 때 적용하는
어조·문체·용어 기준입니다. 영어(`/en/`) 등 다른 로케일 페이지를 만들거나
검수할 때 이 문서를 기준으로 삼습니다.

## 1. 브랜드 보이스 (Voice)

- **전문적이고 신뢰감 있게**: 기술 의사결정자(엔지니어, 구매·기획 담당자)를
  독자로 가정합니다. 근거 있는 자신감을 전달하되 과장하지 않습니다.
- **명료하고 간결하게**: 한 문장에 하나의 메시지. 불필요한 수식어와 중복을
  피하고 핵심 사양·가치를 앞에 둡니다.
- **객관적 사실 우선**: 성능·수치·표준은 정확하게. 마케팅 수사보다 검증
  가능한 사실로 설득합니다.
- **일관된 격식**: 전 채널에서 동일한 격식 수준을 유지합니다(아래 문체 참조).

## 2. 문체 (Style)

### 한국어
- 종결어미는 **합쇼체("~합니다 / ~입니다")**로 통일합니다. 평서체("~한다")나
  반말체는 사용하지 않습니다.
- 능동태를 기본으로 하고, 책임 주체가 모호해지는 과도한 피동("~되어집니다")을
  피합니다.
- 문장은 짧게. 한 문장이 3줄을 넘기면 분리합니다.

### 영어
- **미국 영어 철자**(optimize, color, center)를 기준으로 합니다.
- 문장 케이스(Sentence case)를 기본으로 하되, 제품명·고유명사는 정식 표기를
  따릅니다. 제목에 불필요한 Title Case 남용을 피합니다.
- 능동태·현재 시제를 선호하고, 한 문장에 하나의 핵심만 담습니다.

## 3. 고정 용어집 (Glossary)

### 번역하지 않고 원문 유지 (영문 그대로)
- 제품·기술 약어: **HBM, DRAM, SSD, DDR, GDDR, LPDDR, UFS, eMMC, CXL, MCP,
  NFC, TSV, PIM, DDI**
- 사업/브랜드명: **Samsung, Foundry, SAFE™, SOC-Developer, DS Open-Ecosystem,
  CONNECT, B2B Workplace**
- 단위: **GB, TB, Gbps, Gb/s, nm, GB/s** — 숫자와 단위 사이 표기는 원문 규칙을
  따릅니다(예: `36 GB`, `13.0 Gbps`).

### 표준 번역어 (로케일별 통일)
| English | 한국어 |
|---|---|
| Overview | 개요 |
| Products | 제품 |
| Applications | 응용처 |
| Support | 고객지원 |
| Technologies | 기술 |
| News & Events | 뉴스 & 이벤트 |
| Sustainability | 지속가능경영 |
| About Us | 회사 소개 |
| Related contents | 관련 컨텐츠 |
| AI accelerator | AI 가속기 |
| bandwidth | 대역폭 |
| power efficiency | 전력 효율 |
| data center | 데이터센터 |

> 새 용어가 나오면 이 표에 추가해 로케일 간 일관성을 유지합니다.

## 4. 표기 규칙 (Formatting)

- **상표 기호**: 정식 표기에 포함된 ®, ™ 는 그대로 유지합니다(예: `SAFE™`,
  `NVM Express®`). 임의로 추가·삭제하지 않습니다.
- **약어**: 대소문자는 공식 표기를 따릅니다(HBM4E, 1c DRAM, 4nm). 문장 중간에서
  임의로 소문자화하지 않습니다.
- **숫자/단위**: 원문 수치를 변경하지 않습니다. 천 단위 구분, 소수점, 단위 간
  공백은 원문 규칙을 따릅니다.
- **각주·면책 문구**: 법무 검토를 거친 면책(disclaimer)·각주 문구는 의미가
  바뀌지 않도록 보수적으로 번역하고, 임의로 요약·생략하지 않습니다.

## 5. 피해야 할 표현 (Avoid)

- 근거 없는 최상급·절대 표현("세계 최고", "완벽한", "유일한")은 출처·검증이
  있을 때만 사용합니다. 원문에 없는 과장은 추가하지 않습니다.
- 구어체 감탄·이모지·느낌표 남발.
- 직역투로 어색해진 문장(원문 어순을 그대로 옮긴 번역체). 의미 단위로 자연스럽게
  재구성합니다.
- 로케일에 맞지 않는 통화·날짜·연락처 형식.

## 6. 대상 독자 (Audience)

- 1차: 글로벌 기술 의사결정자 및 엔지니어 (B2B)
- 2차: 파트너·투자자·미디어
- 지역화 시 해당 로케일의 공식 채널·법적 링크·연락처로 현지화합니다.

## 7. 다국어 운영 구조 (Localization Architecture)

이 사이트는 Edge Delivery Services(EDS) + Document Authoring(DA) 백엔드를
사용합니다. 클래식 AEM Sites의 MSM(Live Copy/롤아웃 상속)은 이 스택에 없으므로,
"원본 변경 → 번역본 자동 반영"을 다음 두 계층으로 구현합니다.

### 7.1 코드 레벨 UI 문자열 → 콘텐츠(플레이스홀더 시트) + 코드 폴백
- 블록이 주입하는 UI 문자열(버튼 라벨, ARIA 등)은 **콘텐츠로 관리**합니다.
  작성자가 DA에서 로케일별 **placeholders 시트**를 편집하면 코드 변경 없이
  반영됩니다.
- 시트 경로(공유 프래그먼트와 동일 규칙): 기본 로케일 `/placeholders.json`,
  영어 `/en/placeholders.json`. 두 열 **Key | Value**:
  | Key | Value |
  |---|---|
  | cards-content.loadMore | 더 보기 (en 시트는 "See more") |
- 동작: `scripts.js`의 `loadEager`가 페이지 로드 시 현재 로케일의 시트를 한 번
  가져와 캐시합니다. 블록은 `t('key')`로 동기 호출하고, `scripts/i18n.js`는
  **시트 값 → 번들 사전(코드 폴백) → 기본 로케일 → 키** 순으로 해석합니다.
- `scripts/i18n.js`의 `DICTIONARY`는 **빌드 타임 폴백**입니다. 시트가 없거나
  키가 비어 있어도 빈 라벨이 노출되지 않도록 보장하는 안전망이며, 평상시
  편집은 시트에서 합니다.
- **새 UI 문자열**: 시트에 행 추가(+ 폴백이 필요하면 `DICTIONARY`에도 추가) →
  블록에서 `t('key')` 호출.
- **새 로케일**: ① `getLocale()`에 경로 규칙 추가 → ② `/{locale}/placeholders.json`
  시트 생성. (블록 코드는 변경 불필요)
- 로케일 판별: `/en/*` → `en`, 그 외 → 기본값 `kr` (`getLocale()`).

### 7.2 공유 프래그먼트 → 로케일 경로 자동 해석
- nav·footer 같은 공유 프래그먼트는 `localizedFragmentPath('/nav')`로 경로를
  해석합니다. en → `/en/nav`, 기본 → `/nav`. 블록 코드에 경로를 하드코딩하지
  않습니다.

### 7.3 본문(산문) 콘텐츠
- 페이지 본문은 로케일별 콘텐츠 프래그먼트(`/kr/...`, `/en/...`)로 존재합니다.
- 원본(한국어) 변경 시, 해당 페이지의 import 스크립트(`tools/importer/
  import-*-en.js`)를 다시 실행해 영어 본문을 **재생성**합니다 — 수동 트리거
  방식의 롤아웃입니다. 이때 본 가이드(어조·용어집)를 품질 기준으로 적용합니다.
- 레이아웃·블록·이미지·수치 등 언어 비종속 요소는 블록 CSS/JS를 공유하므로
  자동으로 모든 로케일에 반영됩니다.

> 새 UI 문자열이 생기면: ① `scripts/i18n.js` 사전에 키 추가 → ② 블록에서
> `t('key')` 호출. 새 로케일을 추가하면: 사전의 각 항목과 `getLocale()`에 해당
> 언어 코드를 더하고, 콘텐츠 프래그먼트를 해당 경로에 생성합니다.

## 8. AI 에이전트용 메타데이터 (machine-readable, 비표시)

사용자에게는 보이지 않지만 검색엔진·AI 에이전트가 읽는 **schema.org JSON-LD**를
`<head>`에 주입합니다. 구현: `scripts/seo-jsonld.js` (페이지 로드 lazy 단계에서
1회 실행, 가시적 DOM 추가 없음).

### 8.1 요약(Summary) → WebPage description
- 페이지 메타데이터 **`summary`**(없으면 표준 `description`)를 읽어
  `{ @type: WebPage, name, description, url, inLanguage }` JSON-LD로 출력합니다.
- 작성자는 DA 페이지 메타데이터에 `summary` 항목을 추가하면 됩니다(선택).
  값이 없으면 이 블록은 생성되지 않습니다.

### 8.2 FAQ → FAQPage (기존 FAQ 블록 재활용)
- 페이지에 이미 있는 **FAQ 블록(`.accordion-faq`)** 의 질문/답변을 그대로 읽어
  `{ @type: FAQPage, mainEntity: [Question/Answer …] }` JSON-LD로 변환합니다.
- 별도 콘텐츠 작성이 필요 없습니다 — 본문 FAQ가 곧 에이전트용 FAQ가 됩니다.
- 로케일 무관: KR 페이지는 한국어 Q&A, EN 페이지는 영어 Q&A가 자동 반영됩니다.

> 즉 작성자 작업은 (선택) 페이지 `summary` 메타 입력뿐이며, FAQ는 본문 블록에서
> 자동 생성됩니다.
